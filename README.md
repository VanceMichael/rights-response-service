# 影视保护通知的授权范围与异议复核

作品权利、委托、发布项和异议送达资料均为演练。发布项由平台、链接标识和内容摘要共同识别。

项目包含两部分：

1. **合成资料与协作方协议回放工具**（`data/`、`partner/`）：描述输入事实与外部流水观测，不代表项目已对任何申请作出决定。
2. **业务办理服务**（`app/`）：持久化 HTTP 服务，办理提交、法务核准、平台送达跟进、补件、上传者异议独立复核与状态查询。仅处理本地合成作品与已登记合作平台，不抓取真实网站、不识别侵权内容、不代替法务作法律结论。

使用 Python 3.11，标准库实现，无第三方运行依赖。领域字段及协作方约定见 [资料约定](docs/contracts.md)，业务规则、接口与演练流程见 [业务服务运行文档](docs/service.md)。

`data/catalog.json` 保存原始记录和演练角色，`partner/commands.json` 保存外部已定义流水的观测片段。业务状态与协议回放数据分别保管在各自 SQLite 文件中。

## 运行自动检查

```sh
python3 -m unittest discover -s tests -v
```

检查覆盖授权范围、补件与冲突、法务核准边界、平台能力差异、送达中断与迟到回执、
异议工作日期限与独立复核，以及“授权撤销、异议期限与迟到平台回执在同一发布项相遇”
的完整结果（见 `tests/test_convergence.py`）。

## 启动本地协作方回放

```sh
python3 partner/server.py --port 8765 --state partner-state.sqlite3
```

启动后输出实际端口，`GET /health` 可查询存活。按 `docs/contracts.md` 发起协议请求及查询；重启使用同一状态文件会保留已受理流水。

## 启动业务办理服务

```sh
python3 -m app.main --port 8080 --state app-state.sqlite3 \
    --replay-base-url http://127.0.0.1:8765
```

首次启动自动从 `data/catalog.json` 引导主数据（人员、作品、权利、委托、平台、
发布项、日历），不替业务作出任何审批结论。请求以 `X-User-ID` 标识演练身份，
以 `X-Current-Time`（带时区）注入演练时刻；默认仅监听环回地址。重启使用同一
`--state` 文件保留全部业务数据，换全新文件可开始独立演练。
